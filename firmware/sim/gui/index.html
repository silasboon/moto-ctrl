Battery / engine simulation

Battery 13.2 V

engine_running and the low-voltage cutoff are REAL, derived by mc_diag from this battery voltage every tick (thresholds + hysteresis configurable in the Diagnostics panel below) — dragging this slider exercises the actual on-target logic, not a stand-in. The "engine running" checkbox is sugar: it nudges the battery voltage to a value that makes the real derivation land where you asked (see sim_protocol.h) rather than setting the flag directly.

Outputs (12 channels)

Toggles both TURN_L and TURN_R together (REJECTED if neither is assigned a function below). A channel's mode (plain on/off, PWM dimming, turn-signal blink, or brake-flasher pulse pattern) and the turn auto-cancel timer / blink period / brake pulse timing are all set in the Config JSON panel further down — assign a channel's function to turn_l/turn_r/brake there, set its "mode" to flash_turn/flash_brake to see it blink/pulse; otherwise the switches above just toggle it plain on/off, same as any other channel.

Toggling goes over the real COMMAND channel (SET_OUTPUT), authenticated — for a turn_l/turn_r channel this also does mutual exclusion and arms the auto-cancel timer device-side, same as a real handlebar button would. "current (mA)" injects a raw current-sense reading (SIM_CH_DEBUG) for that channel; the fault badge below it is no longer settable — it's mc_diag's own real classification of that current against the channel's configured thresholds (Diagnostics panel below), same as it would be from real hardware. A channel suppressed by the low-voltage cutoff always reads 0mA/none here, same as a commanded-off channel.

Per-channel thresholds and the low-voltage/engine-running voltages ride the exportable JSON config (Config panel); board calibration is its own blob and is NOT wiped by ownership transfer (it describes this simulated "board", not the outgoing owner). "Learn" samples the channel's current live current draw and sets its open-load threshold from it — the channel must be ON.

Virtual buttons

Press/hold/combo timing is evaluated by the real mc_input engine in the sim (10ms poll). Short presses feed the lock cheat-code buffer below when the bike is LOCKED, AND dispatch every action bound in the Config JSON's inputs.short_press_action[button], which is a LIST (1 = toggle TURN_L, 2 = toggle TURN_R, 3 = hazard press, 256 + N = toggle output N) — both happen independently, the same button can do both. Hold (mousedown) also simulates a maintained switch for the ignition-switch input, or outputs.brake_switch_input. Generic combo matches (unrelated to the cheat-code) are still just logged — no action bound to them yet.

The cheat-code is entered physically via the Virtual buttons above (short-press each button in sequence within the window) — it is never sent as a set/clear/test payload's plaintext to unlock anything; the device only ever compares a salted hash. There is no separate debug op for the ignition-switch input — assign one of the 8 virtual buttons above as the switch input and hold it (mousedown) to simulate the switch being ON.
